## 1. UI：向 Schale-Library / LyricsKara 靠拢（清新易用 + 操作逻辑）

### 1.1 现状

`launcher/theme.py` 已在**方法层**借鉴两站（LyricsKara 的衬线刊头/等宽 meta/舞台层次，
Schale 的分段导航/封面卡/留白），但整体气质仍偏「安静工具台」，
且 `docs/UI-AESTHETIC-DESIGN.md` 现行规范**禁止**照抄 BA 蓝 `#1289F0` 与 LyricsKara 近黑画布。

参考站技术事实（本次调研）：

| 站 | 栈 | 可借鉴 |
|----|----|--------|
| Schale-Library | Next.js + TS（shadcn 风格组件体系） | 轻透画布、分段导航、封面优先网格、内容留白 |
| LyricsKara | 静态 + 单 `site.css` | 字阶（衬线标题/等宽 meta/0.08–0.4em 字距）、settle 缓动 `cubic-bezier(0.22,1,0.36,1)`、按作品注入主题色变量的做法 |

### 1.2 视觉清新化（M1a）

- 画布/表面整体提亮一档，扩大留白（`PAD_X`/卡片间距），弱化 hairline。
- 保留现行青绿 accent；**如需更接近 Schale 的清爽感**，出 2–3 套候选色板（含一套浅蓝绿）由产品拍板后更新 §0.2 token 表 —— 不默认改色。
- 动效克制：hover/选中过渡用 settle 曲线思路（Tk 内以状态切换近似），不加发光霓虹。
- 「按音色注入主题色」：借 LyricsKara `--band` 思路，音色封面主色可淡淡地染舞台带（仅背景 wash，不动全局 token）。

### 1.3 操作逻辑（M1b，重点）

1. **首次运行三步向导**：装 VB-Cable → 选输入（真麦）/输出（CABLE Input）→ 试音验证
   （播放测试音 + 输入电平表 + 接线自检）。把最大客服成本「接线」前置解决。
2. **主路径三击可达**：首页 = 选音色 → 大启停 → 状态徽章；高级参数默认收起。
3. **设置分级**：常用（设备/监听/快捷键）与高级（Index/性能/引擎）折叠分层，可搜索定位。
4. **模型页**：搜索/排序/标签；空态引导去「更新」页下载音色。
5. **状态与报错人话化**：统一徽章语言；失败给下一步动作（如「输出设备被占用 → 换设备或重启引擎」）；
   「其他」页加一键导出诊断包。

**验收标准**：新用户不看文档，5 分钟内完成第一次变声。

## 2. RVC 推理优化（不破坏已训练模型兼容）

**原则**：只动推理侧代码，`.pth` / `.index` 格式与语义不变 → 旧模型全兼容。
训练质量上限由模型本身决定；v3 底模未发布，推理侧不可能超越训练质量，能做的是
**降延迟、稳音质、补 DML 短板**。

### P0 先建基准（做任何优化前）

- benchmark 脚本：固定 wav 回放，量化 `fea / index / f0 / model` 四段耗时
  （`rtrvc.py` 日志已打点）与端到端延迟；输出对比表。
- 音质回归：优化前后同输入输出做频谱距离 + 人工试听，防「变快变糊」。

### P1 低风险性能（预计端到端延迟收益 10–30%）

- `torch.no_grad` → `torch.inference_mode`；消除热路径强制同步
  （`rtrvc.py:392` 的 `feats...cpu().numpy()` 每块一次 GPU→CPU 同步）。
- **Index 检索**：`big_npy` 常驻 GPU 用 torch top-k 替代每块 CPU faiss flat 搜索；
  或 IVF + nprobe 调优；大 index 内存映射。
- 预分配缓冲 / pinned memory；`cache_pitch` 滚动改 `roll` 避免每块 `clone`。
- F0 预设化：实时默认 fcpe（快），rmvpe 作为「质量优先」预设（代码已支持，落到 UI 预设）。

### P2 结构性提速

- `torch.compile`（视 Runtime torch 版本；cu118/cu128 的 torch2.x 可用；DML 不适用）。
- **ONNX Runtime 后端**（`export_onnx.py` / `models_onnx.py` 已有）：
  首次从 `.pth` 导出 onnx 并缓存，之后直接加载 —— 对 A/I 卡（DML fp32）是最大提速点，
  也不改动原模型文件。
- CUDA Graphs / 固定 block 形状（配合性能预设）。

### P3 质量（不训练）

- 可选后处理链：降噪门（`tools/torchgate` 已有）、轻 EQ / de-esser（`tools/dsp_fx.py` 已有）、响度归一。
- F0 平滑/中值滤波选项、轻声断音处理（fcpe 阈值已调过一轮）。
- crossfade / SOLA 参数并入性能预设。

## 3. 功能可用性与 A/I 卡适配现状

### 3.1 已验证事实

- 本次在 Linux 容器跑产品单测：**72 passed / 11 skipped**（跳过项为 Windows / Runtime 依赖）。
  产品逻辑层是绿的。
- 功能侧（交接文档）：单窗口变声、底栏热控、按音色参数、快捷键、监听自听、
  在线更新/商店、快速退出均已实现。

### 3.2 缺口

- **最大缺口 = 分显卡全量包实机验收**（nvidia / amd / nvidia50 三包均未验收）。
- A/I 卡**代码侧已齐**：`gpu_backend` 探测、`--dml` / `TM_USE_DML`、
  `configs/config.py` DML 设备与 onnxruntime 切换、`rmvpe.onnx`、amd variant 构建、`package_meta.json`。
  三套 RVCMAX Runtime 已在打包机。**尚未**：amd / nvidia50 全量包构建 + 真机验收。
- DML 已知限制（如实告知用户）：fp32（慢于 CUDA fp16，P2 的 ONNX 后端是补偿）、
  crepe 不可用（自动 fallback fcpe）。

### 3.3 验收计划

- 出「3 变体 × 核心用例」验收矩阵 checklist（启停/切音色/热更参数/监听/快捷键/强杀恢复/更新）。
- 自动冒烟脚本纳入 `scripts/run_tests.bat` 可选段。

## 4. 其他建议

| 优先 | 项 | 说明 |
|------|----|------|
| 高 | exe 代码签名 | PyInstaller 无签名易触发 SmartScreen / 杀软误报，直接影响大众版口碑 |
| 高 | CI：GitHub Actions 跑 `tests/` | 当前只有本机 `run_tests.bat`；push 即验证 |
| 中 | 一键诊断包 | 日志 + 设备列表 + 配置（脱敏）打 zip，客服效率 |
| 中 | worker 崩溃自动拉起一次 + 提示 | 现有单实例/清孤儿基础上补自愈 |
| 中 | 中文/特殊字符路径预检 | 原版引擎限制，启动时检测并提示换路径 |
| 中 | 音色商店版权合规提示 | 分发音色前置声明 |
| 低 | gui_patch 增量更新加回滚 | 更新失败可退回上一版 |
| 低 | 图文快速上手（大众版） | 配合向导，进一步降支持成本 |
