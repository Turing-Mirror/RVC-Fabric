# 1.7.2 发版依赖核对

核对日期：2026-11-01。范围为前端锁文件、构建与测试入口；安装版使用编译后的静态前端，不运行 Vite 开发服务器或 Node 测试工具。

## 本次处理

- Vite 7.3.6 升级到 7.3.7。现有 Windows 开发入口注册了 `/__open-in-editor`，其文件参数进入内嵌的 launch-editor。7.3.7 包含 launch-editor 2.14.2 的修复，保持 Vite 7 的兼容范围。[官方修复说明](https://github.com/vitejs/launch-editor/security/advisories/GHSA-587h-7wmj-h5pm)
- Vitest 更新到 4.1.12，更新同版本的配套包，修复开发阶段 mock 注册端点的权限问题。产品没有配置公告所述独立 mock 插件。[官方公告](https://github.com/vitest-dev/vitest/security/advisories/GHSA-xp26-3454-mjgp)
- 通过 npm 在父依赖允许的范围内更新 brace-expansion、source-map-js、Zod，保留不同依赖链所需的主版本。前两者用于固定 glob 和 CSS/source-map 构建；Zod 仅由 ESLint 工具链引入。[brace-expansion 公告](https://github.com/juliangruber/brace-expansion/security/advisories/GHSA-q2hr-2g5m-vwhr)、[source-map-js 修复](https://github.com/7rulnik/source-map-js/releases/tag/v1.2.2)、[Zod 修复](https://github.com/colinhacks/zod/pull/6652)

## 保留告警及边界

- Happy DOM 20.13.2 仅供 Vitest 使用。当前默认关闭 JavaScript 求值；项目测试渲染固定的本地 React 组件，没有导入不受信 HTML、模块脚本、iframe 或外部样式表。未发现公告中的模块注入、iframe/样式表 SSRF 在现有测试输入上可达。完整修复需要升级至 21.0.4 或更新版本，跨主版本的测试环境升级单独验证。[21.0.0 变更](https://github.com/capricorn86/happy-dom/releases/tag/v21.0.0)、[21.0.4 修复](https://github.com/capricorn86/happy-dom/releases/tag/v21.0.4)
- minimatch 的剩余告警传播到 ESLint / typescript-eslint。漏洞要求攻击者控制 glob 且启用 `optimizationLevel >= 2`；本项目使用固定 glob 和默认优化级别，没有开启 TypeScript projectService。保留各父包支持的 minimatch 主版本，不强制覆盖成 11，也不采用自动审计提出的 ESLint 降级方案。[维护者公告](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249)

以上边界针对当前构建和测试配置，不表示这些依赖本身没有漏洞。若引入外部 HTML、动态 glob 或相关开发服务，须提前重新评估；最迟于 2026-11-15 的依赖维护复核。发布验证分别记录生产依赖审计、全部开发依赖告警、前端测试和生产构建结果，不将生产依赖零告警表述为整个工具链零告警。
