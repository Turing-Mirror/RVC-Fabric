# 语音转换：多音色对比、单条音高、结果映射（后端任务卡 v1）

界面由另一位负责，本卡只做后端。完成后不要提交，留在工作区等审查。

## 背景

语音转换窗口要新增三件事：

1. 一条音频用多个音色各转一遍，方便对比。
2. 清单里单独给某几条设音高，覆盖整批的音高。
3. 转换完成后，界面要知道每个源文件对应哪个输出文件，用来做「原声 / 转换后」切换试听。

界面会自己把「条目 × 音色」展开成清单，并按音色分组排好顺序，后端照单执行即可。

## 接口约定

### 清单条目（`sts_start` 的 `manifest`，以及 worker 请求里的 `manifest`）

现在是 `{src, rel}`。新增四个可选字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `pitch` | int | 本条音高，覆盖请求级 `pitch`。缺省或 null 时用请求级。 |
| `model` | str | 本条用的音色 `.pth` 路径。缺省时用请求级音色。 |
| `index` | str | 本条的 `.index` 路径。缺省时：若 `model` 也缺省，用请求级 index；若给了 `model` 而没给 `index`，按该音色在库里的绑定解析（与 `resolve_model` 同一规则），解析不到就不用 index。 |
| `tag` | str | 输出文件名标签。非空时输出名为 `<原文件名>_<tag>.<ext>`（tag 清洗成 Windows 合法文件名，最长 40 字符）；为空时保持现在的 `<原文件名>_rvc.<ext>`。重名仍按现有规则加序号。 |

### 执行顺序与模型切换

- 严格按清单顺序处理，不重排。界面依赖「已处理条数」划分重试范围。
- 当前条目的音色与已装载的不同时才重新装载（复用 `_prepare` 里换音色只付 net_g 的逻辑），hubert / rmvpe 不重读。
- 装载失败：该音色下的条目全部记为跳过（原因写清楚），继续处理后面的条目，不整单失败。
- 进度：总数仍是清单条数；换音色时可以发一条 `phase=run` 的提示，文案沿用现有风格。

### 结果

- worker 的 `done` 事件与 `sts_start` 的返回值新增 `results: [{src, dest, tag}]`，与成功条目一一对应、按处理顺序。`files` 保留不变（兼容）。
- `skipped` 中每条、以及 `phase=skip` 事件，新增 `tag` 字段。
- 冷路径和热路径（`run_hot`）都要给出 `results`。

### 热路径

清单里只要有任何一条的 `model` 与请求级音色不同，就不走热路径，直接走冷路径。只有单音色时才允许热路径。热路径同样要支持条目级 `pitch` 与 `tag`。

## 涉及文件（参考，不限于此）

- `tools/sts_core.py`：`collect_manifest`、`unique_dest`、`run_batch`
- `tools/sts_worker.py`：`run_request`、`_prepare`
- 热路径对应的 worker 代码（`run_hot` 发给实时 worker 的那条请求的处理处）
- `app/src-tauri/src/sts.rs`：清单透传、路由判定、返回值拼装
- `app/src-tauri/src/lib.rs`：`sts_start` 无需新增参数（新字段都在 `manifest` 里）

## 完成标准

1. `python -m unittest tests.test_sts_core tests.test_sts_worker` 通过，并为以下情况补测试：条目级音高覆盖；`tag` 命名与清洗；多音色顺序处理且只在音色变化时重装；某音色装载失败时只跳过它的条目；`results` 与成功条目一一对应。
2. `cargo test --lib`（在 `app/src-tauri`）通过；为「清单含不同音色时不走热路径」补测试。
3. `python -m unittest discover -s tests` 中除缺 torch 导致的 `test_accel_policy` 外全部通过。
4. 旧清单（只有 `src`、`rel`）的行为与现在完全一致。
5. 最后用中文简短列出改了哪些文件、各做了什么。
