# Neptune 手机配对与音频接入

手机配对集成在“其他”页，复用桌面当前 RVC worker、音色、预设及音频库。浮动窗口入口和手机配对位于页面最顶部；Dock 只增加移动端运行状态及已配对提示，路由和设备管理保留在配对区域。

## 使用

在“其他 → 手机配对”显示二维码，选择手机可访问的网卡。RVC Fabric Mobile v4 支持离线相机扫码、二维码图片导入和手动粘贴。配对成功后，手机明确开启麦克风，再从手机或 Dock 开启变声。

Windows 首次提示网络访问时，允许 RVC Fabric 使用当前专用网络。二维码中的地址和端口以当前界面为准。

使用手机输入时，Dock 显示“移动端变声中”；已连接但停止变声时，在“引擎就绪”下方显示“已配对移动端”。可以在配对区域切回电脑输入，手机心跳不会覆盖该选择。

电脑监听、声音输出设备、输入降噪、输入与输出增益都在配对区域控制。增益和降噪使用现有引擎配置，与桌面设置保持同步。两路电脑输出默认关闭，停止、断开及撤销配对会关闭已经排队的硬件输出。手机监听独立控制，外放监听继续禁用。

## 生命周期与协议

- 应用启动只读取配对元数据。用户明确点击配对后，监听选中的本机 IPv4 地址；默认端口 8787，冲突时使用空闲端口。没有自动监听全部网卡的行为。
- 二维码使用 `rvcfabric://pair?data=...`，携带版本、实例标识、地址及两分钟有效的一次性票据。刷新和成功兑换都会使旧票据失效。
- `POST /v1/pair` 兑换独立设备凭据。其余 HTTP 和 WebSocket 请求必须携带 `Authorization: Bearer ...`。电脑在 `User_Data/mobile/pairing.json` 中仅保存凭据摘要。
- 同时允许一个在线手机。手机先连接，再显式开启麦克风；设备心跳与麦克风状态分开。连接丢失、关闭连接、撤销设备、手机停止采集都会停止对应移动音频。
- 实时音频为 48 kHz、单声道、PCM16，网络帧为 20 ms。Rust 负责网络与可选输出，`tools/mobile_audio.py` 通过带凭据的回环连接接入既有 worker 的共享内存接口。
- 协议版本仍为 1。新增 `pairing`、`microphone_control`、`desktop_session` 能力，不将桌面通用调用接口暴露到局域网。旧客户端显式开始时继续兼容其连接即采集的行为。

HTTP 网络连接适用于受信任的局域网。局域网协议只提供移动音频和文件操作，不开放任意路径、脚本执行或桌面命令。

## 音频与文件

输入、输出、插播共用现有推理链，停止后清空待发送数据。插播探测、解码启动及退出不持有实时音频锁；最大十六路，沿用音频库裁剪、循环、音量和定位。手机输入固定采样率，切换不同采样率的模型不会重建手机连接。

上传限制为 64 MiB，解码最长十分钟，最多八个不同音色。转换复用桌面文件转换引擎，任务与下载均按设备授权。转换占用引擎时不能并发开始实时推理；转换前由内置服务暂停的实时任务，仅在连接和操作状态没有改变且未取消时恢复。

配对、上传和转换历史位于 `User_Data/mobile/`。启动时清理超过七天的生成缓存，未完成任务在桌面重启后标记为中断。关闭网络不会撤销已记住设备；取消配对才撤销凭据。

## 开发与验证

主要模块为 `app/src-tauri/src/mobile.rs`、`mobile/`、`tools/mobile_audio.py`、`useMobile.ts` 和 `MobileSection.tsx`。新模块分别处理配对、网络、PCM、目录、插播和文件任务，桌面原有命令仍负责引擎启动与停止。

常规检查为前端构建与测试、`cargo test --lib`、移动 PCM／环形缓冲／模型切换相关 Python 测试。`scripts/check_mobile_bridge.py` 可对独立桌面实例验证真实推理、文件转换、重连和撤销，需安装 aiohttp，并明确指定测试注册表与输出目录。测试配置必须关闭硬件输出。

独立测试根目录应复制 `tools/` 和 `gui_v1.py`；不要将 `tools/` 建成指向正式目录的联接，否则 Python 路径解析会让 worker 使用正式目录。模型和 Runtime 可以复用，但配置、注册表、缓存及日志必须隔离。

打包流程会移除本机个人音色与已下载分离模型权重，保留分离配置和空的音色目录。APK 保留既有安装身份；真实 Root／Shizuku 应用注入和主观声音质量仍由对应物理设备验收。
