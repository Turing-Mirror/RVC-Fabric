# 音频库阶段八实现状态

更新于 2026-09-23，分支 `tm-release`。本阶段接续[阶段七](音频库阶段七实现状态.md)。

## 已实现

- 原生混音器在打开输出流前预留 16 个独立音乐槽；麦克风仍占独立轨道。音频回调只在固定槽和有界队列之间移动音轨，不在回调中创建、销毁解码器或重开设备。16 是同时播放的资源预算，不限制音频库条目数。
- 默认“播放到语音”替换全部外发音频，另有明确的“叠加播放到语音”入口。新片段先完成查找、解码准备和格式检查，再替换旧片段；准备失败时旧片段继续播放。叠加达到预算时拒绝新增，已有实例不受影响。
- 每个实例有独立 ID、进度、暂停和停止操作。音频页列出活动实例；“停止全部音频”会取消尚未完成的启动请求。悬浮窗显示最近触发的实例及其余实例数量，控制只作用于该实例；点击数量可唤出主窗口的音频页。
- 旧启动请求在新请求或停止全部之后返回时不会恢复播放；变声启动期间不会接收新的音频准备请求。变声麦克风轨不受单个音频实例停止影响。

## 本机检查

- 音频核心多槽混音与队列定向测试通过；macOS 和 Windows 目标 Rust 静态编译通过。
- 音频页交互测试、TypeScript 类型、ESLint、八语言包一致性检查通过。

## 待继续

- Windows 实机确认 1、4、16 路叠加的 CPU、内存、欠载、输出端行为与实际听感；本机不代替虚拟声卡验收。
- 快捷键、循环、定位、音量与短淡入淡出尚未接入；本地监听仍沿用现有路径，未统一到原生总线。
