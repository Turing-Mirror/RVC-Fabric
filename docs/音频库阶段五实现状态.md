# 音频库阶段五实现状态

更新于 2026-09-23，分支 `tm-release`。本阶段延续[阶段四](音频库阶段四实现状态.md)。

## 已实现

- 旧 `AudioIoProcess` 增加只采集模式。此模式保留麦克风共享输入与事件合同，但不选择或打开目标输出设备；现有 RVC／DSP 默认运行路径不变。
- 冻结 Python 与原生端共用的有界 PCM 布局：64 字节头，`FABPCM01` 标记、版本、采样率、声道数、帧容量、epoch、读写帧序号；后续为交错 float32 帧。两端均按完整帧处理，过期 epoch 不写入，满环丢弃新块而不阻塞推理。
- Windows 原生端已可创建有名共享映射，并按输出时钟读取整帧。积压超过允许时长时跳过旧人声帧，且不会提前释放仍在读取的区域。映射读取不在声卡回调中执行。
- Python 生产者支持声道转换与必要时的重采样，单元测试覆盖环回绕、满环、过期 epoch；Rust 合同测试覆盖头部及边界。Windows 目标静态编译检查通过。

## 尚未完成

- 共享映射尚未接入 RVC／DSP 的实时输出写入点或原生混音流。本阶段不改变用户可见的变声与音频互斥行为。
- 需要完成持久原生输出服务、两套引擎的 PCM 接入、生命周期切换与监听统一，之后再交由 Windows 实机验证。当前无实际虚拟声卡效果结论。
