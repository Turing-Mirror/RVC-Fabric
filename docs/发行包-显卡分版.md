# 发行包显卡分版（对齐官方 RVC + RVCMAX）

> **结论先说**：官方「A 卡 I 卡加速支持」**不是**只在启动命令上加一个参数。  
> 完整路径是：**单独的一套运行环境（依赖/绿色 Runtime）+ 启动时走 DirectML（`--dml`）**。  
> 参数只在**正确环境**里切换设备；没有 DML 版 torch/onnxruntime，只写 `--dml` 没用。

---

## 1. 官方到底怎么做的（README / Changelog 原文逻辑）

### 1.1 安装层：两套依赖

| 用户 | 安装方式 |
|------|----------|
| N 卡 | `pip install -r requirements.txt`（CUDA 版 torch 等） |
| Windows A/I 卡 | `pip install -r requirements-dml.txt`（**torch-directml**、**onnxruntime-directml** 等） |
| Linux AMD | `requirements-amd.txt`（**ROCm** 版 torch，不是 DML） |
| Linux Intel ARC | `requirements-ipex.txt`（IPEX） |

`environment_dml.yaml` 里是 **CPU 版 torch + torch-directml**，与 N 卡 **cu118 torch** 不是同一环境。

### 1.2 发行层：两个整合包

| 包 | 说明 |
|----|------|
| `RVC1006Nvidia.7z` | N 卡绿色 Runtime |
| `RVC1006AMD_Intel.7z` | A/I 卡绿色 Runtime |

### 1.3 启动层：环境正确之后再 `--dml`

| 路径 | 启动 |
|------|------|
| N 卡 | `go-web.bat` / `go-realtime-gui.bat` |
| A/I 卡 | `go-web-dml.bat` 等，WebUI **`--dml`** |

`configs/config.py` 在 `dml=True` 时：

- `import torch_directml` → `device = torch_directml.device(...)`
- 半精度关掉（fp32）
- 把 `onnxruntime` 与 `onnxruntime-dml` 目录按官方方式切换

另：A/I 用户还要 **`rmvpe.onnx`**（DML 音高），N 卡常用 `rmvpe.pt`。

### 1.4 一句话

```
官方 A/I 加速 = 整包环境（DML 依赖） + 启动 --dml
              ≠ 在 N 卡 CUDA 环境里只加 --dml
```

## 2. RVCMAX

除官方两套外，社区/RVCMAX 还有 **50 系** 等专用 Runtime（新架构/新 CUDA）。  
本仓库参考：

```
RVCMAX/
  RVCMAX_Nvidia_xiaoyuan/      # N 卡 CUDA（prefer_dir）
  RVCMAX_AMD_xiaoyuan/         # A/I DirectML（prefer_dir）
  RVCMAX_Nvidia50x0_xiaoyuan/  # 50 系 CUDA（prefer_dir）
```

各包内需有 `Runtime\python.exe`。构建脚本 `prefer_dir` 已对齐上表；`nvidia` 扫描会 **排除** 目录名含 `50` / `50x0` 的包，避免误选 50 系 Runtime。

## 3. 我们最终发布（与官方一致：多完整包）

| 发布目录 | `--variant` | Runtime | 默认加速 |
|----------|-------------|---------|----------|
| `dist/TuringMirror_Voice_Nvidia` | `nvidia` | N 卡 CUDA Runtime | `cuda` |
| `dist/TuringMirror_Voice_AMD` | `amd` | A/I DirectML Runtime | `dml` |
| `dist/TuringMirror_Voice_Nvidia50` | `nvidia50` | 50 系 CUDA Runtime | `cuda` |

每个包内：

- `启动器.exe` / `变声器.exe`
- **该变体专用** `Runtime/`
- `package_meta.json`（标记 variant / accel_default）
- 引擎、`rmvpe.pt` + `rmvpe.onnx`、模型、VBCABLE

包内「加速后端」下拉仅作微调；**分发以整包为准，禁止混用 Runtime。**

## 4. 构建命令

```bat
set TEMP=L:\My project\Grok\TEMP_BUILD
set TMP=%TEMP%

REM N 卡全量（自动 prefer RVCMAX_Nvidia_xiaoyuan）
python scripts/build_release.py --clean --variant nvidia

REM A 卡全量（自动 prefer RVCMAX_AMD_xiaoyuan）
python scripts/build_release.py --clean --variant amd

REM 50 系（自动 prefer RVCMAX_Nvidia50x0_xiaoyuan）
python scripts/build_release.py --clean --variant nvidia50
```

未指定 `--runtime` 时：先 `prefer_dir`，再按关键字扫描；`nvidia` 排除 50 系目录名。

开发机切换 Runtime junction：

```bat
python scripts/sync_from_rvcmax.py --variant nvidia --force-runtime
python scripts/sync_from_rvcmax.py --variant amd --force-runtime
python scripts/sync_from_rvcmax.py --variant nvidia50 --force-runtime
```

产品单测：`scripts\run_tests.bat`

## 5. 代码侧已具备

| 能力 | 作用 |
|------|------|
| `package_meta.json` | 标明本包是 nvidia/amd/50 |
| `accel_backend` 默认随包 | A 卡包默认 `dml`，N 卡默认 `cuda` |
| `TM_USE_DML` / `--dml` | 在**正确 Runtime** 内切换设备（对齐官方） |
| `configs/config.py` | DirectML 设备 + onnxruntime 切换 + rmvpe 路径兼容 |

等你放入 A 卡 / 50 系 Runtime 后：直接按上表 `--variant` 全量打对应包即可。
