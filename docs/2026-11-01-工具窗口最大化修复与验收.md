# 工具窗口最大化修复与验收

对应 [Issue #10](https://github.com/Turing-Mirror/RVC-Fabric/issues/10)。基于 `d845c485`，测试包版本仍为 1.7.1。

## 原因与修改

1. `tools_open` 是异步命令，建窗返回后仍在后台线程。`round_corners` 原来直接在该线程调用 `SetWindowSubclass`；Windows 要求该调用发生在窗口所属线程，原代码忽略了失败返回值。因此工具窗没有接上既有的最大化工作区和客户区处理。现在将初始化派发到 UI 线程，先安装回调再修改边框样式，并记录安装或派发失败。
2. 三个工具共用的 `ToolBody` 限制正文最大宽度为 720px，而底部操作栏铺满窗口。现在正文随可用窗口宽度伸展，保留现有内边距、控件、配色和交互。
3. 增加真实 Windows 窗口回归测试。为使测试程序也能加载 Windows Common-Controls v6，MSVC 构建改由链接器嵌入与 Tauri 默认 manifest 相同的依赖声明；其他平台继续使用原构建路径。

API 限制参见 [Microsoft SetWindowSubclass 文档](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-setwindowsubclass)。

- 前端：41 个测试文件、245 项测试通过；ESLint、TypeScript、翻译键检查、Vite 构建通过。
- Rust：475 项常规测试通过。原生窗口测试默认忽略，单独执行后通过。
- 原生回归测试先在旧代码上失败：工作区回调查询返回 0。修改后验证回调存在、客户区等于窗口外框、最大化矩形等于显示器工作区；连续三次还原均回到原来的位置和大小。
- Edge 中测量以下 9 组布局：正文宽度与内容区一致，页面没有横向溢出，底部操作栏均保持可见。

独立代码审查未发现阻断问题，没有新增运行时依赖、高频轮询或外部数据访问。

## 用户验收

1. 打开 `F:\RVC Fabric-new\rvc-fabric.exe`，从首页进入「语音转换」。
2. 点击右上角最大化按钮。检查任务栏仍正常显示、图标可见可点，窗口底边停在任务栏上方；正文输入框和滑杆应随窗口变宽，底部按钮完整可见。
3. 再次点击同一按钮还原，连续重复三次。每次应回到原来的大小和位置，之后仍能拖动窗口、拖边调整大小。
4. 在小窗口中滚动正文，检查底部操作栏一直可用；切换「音频变声 / 文字合成」后再检查一次。
5. 对「人声分离」「训练音色」各重复最大化和还原。若使用副屏，将工具拖到副屏后再验证，窗口应以该屏工作区为边界。

Computer Use 在本次环境中连续出现截图超时，随后用户按 Esc 停止了界面操作，因此安装后的应用启动和实际任务栏颜色尚未完成目视验收。原生测试证明了工作区和还原几何正确，不能替代上述颜色与图标的最终确认。本次未执行实际音频转换、分离或训练任务。
