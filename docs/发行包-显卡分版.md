# 发行包显卡分版（对齐官方 RVC + RVCMAX）

> **状态**：方案已定；N 卡包已成型。等本机放入 RVCMAX **A 卡 Runtime** 与 **50 系适配包** 后再落地构建。  
> **原则**：最终用户侧与官方一样提供 **多套完整包**，而不是一个包里猜显卡硬切半吊子环境。

---

## 1. 官方怎么分

| 用户 | HuggingFace / 常见命名 | 启动 |
|------|------------------------|------|
| NVIDIA | `RVC1006Nvidia.7z` | `go-web.bat` / `go-realtime-gui.bat`（CUDA） |
| AMD / Intel | `RVC1006AMD_Intel.7z` | `go-*-dml.bat`，WebUI 带 **`--dml`**（DirectML） |

依赖与 Runtime **整包不同**（torch 构建、onnxruntime 厂商 DLL 等），不是改一个开关就能完美跨卡。

---

## 2. RVCMAX 怎么分（本仓库参考）

本地参考目录（请放到 `RVCMAX/` 下，名称可微调但尽量清晰）：

```
RVCMAX/
  RVCMAX_Nvidia_xiaoyuan/     # 已有 · 当前全量包来源
  RVCMAX_*AMD* 或 *DML* / …   # 待你下载：A 卡 / DirectML Runtime
  RVCMAX_*50* 或 *5xxx* / …   # 待你下载：50 系适配包
```

下载后请尽量保持结构类似 N 卡包：

```
RVCMAX_<变体>/
  Runtime/           # 必有 python.exe
  RVC_Core/          # 可选：hubert/rmvpe/ffmpeg 合并源
  User_Data/models/  # 可选预置音色
  VBCABLE/           # 可选
  启动器.exe         # 可忽略，我们用自己的 launcher
```

若压缩包结构不同，解压后把 **含 `python.exe` 的绿色环境目录** 标成 `Runtime` 即可。

---

## 3. 我们最终发布形态（目标）

与官方一致：**多个完整文件夹/压缩包**，用户按显卡选：

| 发布名（建议） | Runtime 来源 | 默认加速 | 说明 |
|----------------|--------------|----------|------|
| `TuringMirror_Voice_Nvidia` | RVCMAX Nvidia | CUDA | 现有主线 |
| `TuringMirror_Voice_AMD` | RVCMAX A 卡/DML | DirectML（`--dml` / `TM_USE_DML=1`） | A/I 卡 |
| `TuringMirror_Voice_Nvidia50`（名称待定） | RVCMAX 50 系包 | CUDA（新架构/新 CUDA） | 50 系专用 |

每个包内仍是：

- `启动器.exe` / `变声器.exe`
- `Runtime/`（该变体专用，勿混用）
- `User_Data/models/`、`VBCABLE/`、`assets/`、引擎源码

**不要**让用户从一个 N 卡 Runtime 里硬跑完整 A 卡官方体验；`accel_backend` 仍可作包内微调，但 **分发以整包为准**。

## 4. 构建命令（落地后）

计划扩展 `scripts/build_release.py`：

```bat
REM N 卡（默认）
python scripts/build_release.py --clean --variant nvidia

REM A 卡
python scripts/build_release.py --clean --variant amd --runtime "RVCMAX\...\Runtime"

REM 50 系
python scripts/build_release.py --clean --variant nvidia50 --runtime "RVCMAX\...\Runtime"
```

输出示例：

```
dist/TuringMirror_Voice_Nvidia/
dist/TuringMirror_Voice_AMD/
dist/TuringMirror_Voice_Nvidia50/
```

打包机 **TEMP 一律 L 盘**（或工程盘），避免占满 C 盘。
