# 发布制品上传流程

Runtime tar、音色包、Setup.exe 这类几百 MB 到几个 GB 的东西，**走 CNB 的
Release 附件，不进 git**。

原因：git + LFS 的模型假设你有一份完整工作副本——改一行 YAML 也得先把几个 GB
拉下来；而且 LFS 对象删不掉，制品换一次版本，旧的永远留在历史里。Release 附件
是按文件寻址的：传一个不需要 clone 任何东西，删一个是真删。

清单本身（`catalog-src/*.yaml` 和编译出的 JSON）仍然走 git——它们是几十 KB 的
文本，正是 git 擅长的。

---

## 一次就能跑完

```bash
. ~/.cnb/agent-token          # 或 export CNB_TOKEN=<PAT>

python scripts/publish_asset.py \
    --tag RVC-runtime \
    --file /path/to/runtime-nvidia-2026.07.21.tar \
    --write-yaml ../RVC-Fabric-Release/catalog-src/runtimes/nvidia.yaml
```

脚本做五件事：建 release（已存在就复用）→ 拿预签名上传地址 → HTTP PUT →
确认 → **回读服务端算的 sha256 和本地比对**。比对不上直接报错，不会留下一个
看起来成功的坏附件。

`--write-yaml` 会把 `sha256` / `size_bytes` / `channel: release` /
`release_tag` 写回清单。用的是逐行替换而不是 YAML 库——那些文件是人工维护的，
注释和字段顺序都有意义，round-trip 一遍会全冲掉。

传完跑一遍校验再提交清单：

```bash
python scripts/build_catalog.py check --strict
python scripts/build_catalog.py build --diff
```

## 权限：必须用个人访问令牌

**`cnb login` 那套 OAuth 拿不到 Release 权限。** `cnb_cli` 这个 OAuth 客户端
注册的范围里根本没有 `repo-release`——授权页上那 12 项 REPO 权限里找不到它，
勾什么都没用。用它调上传接口会得到：

```
403  Missing required scopes: repo-release:rw
```

正确做法是在 CNB 网页端建一个**个人访问令牌**，勾上 Release 读写，然后：

```bash
echo 'export CNB_TOKEN=<令牌>' > ~/.cnb/agent-token
chmod 600 ~/.cnb/agent-token
```

CLI 的凭据优先级是：CodeBuddy 环境 token → `CNB_TOKEN` → `~/.cnb/token`。
所以 `CNB_TOKEN` 会盖过 OAuth 登录的那份。

令牌等同于密码：只放在 `~/.cnb/agent-token`（600 权限，两个仓库之外），
**不要写进任何仓库、不要贴进聊天工具**。泄露了就去 CNB 吊销重建。

---

## ttl 必须是 0

CNB 的附件接口有 `--ttl`，说明是「附件保持的天数。**0 表示永久，最大不能超过
180 天**」。

不显式传 0，附件就可能过期。分发用的制品一过期就是所有用户下载 404，而且不会
有任何告警。`publish_asset.py` 把 `--ttl 0` 写死，不给调。

附件元数据里**没有过期字段**，读接口看不出一个已有附件是不是永久的——所以只能
在上传时保证，事后查不了。

## 手工跑（脚本挂了时的兜底）

```bash
export CNB_TOKEN=<PAT>
REPO=Turing-Mirror/RVC-Fabric-Releases

# 1. 建版本（同一 tag 只需一次；已存在就跳过）
cnb releases post-release --repo $REPO \
    --tag-name RVC-runtime --name RVC-runtime --target-commitish main
#    → data.id 就是 release-id

# 2. 拿上传地址
cnb releases post-release-asset-upload-url --repo $REPO \
    --release-id <id> --asset-name <文件名> --size <字节数> --overwrite --ttl 0
#    → upload_url（12 小时内有效）
#    → verify_url，形如 .../asset-upload-confirmation/<token>/<url编码的path>?ttl=0

# 3. 传
curl -X PUT --data-binary @<本地文件> "<upload_url>"

# 4. 确认
cnb releases post-release-asset-upload-confirmation --repo $REPO \
    --release-id <id> --upload-token <token> --asset-path <path> --ttl 0

# 5. 回读校验
cnb releases get-release-by-id --repo $REPO --release-id <id>
#    → 找 name: <文件名> 那一块，往上看 hash_value，和本地 sha256 比
```

附件块的字段顺序是 `path` → `hash_algo` → `hash_value` → `url` → `name`。
**别用文件名直接 split 输出**：`path` 那行里也含文件名，会切在 `hash_value`
之前，永远读不到哈希。

下载地址：`https://cnb.cool/<org>/<repo>/-/releases/download/<tag>/<文件名>`

## 删一个附件 / 一整个版本

```bash
cnb releases delete-release-asset --repo $REPO --release-id <id> --asset-id <aid>
cnb releases delete-release --repo $REPO --release-id <id>
```

删版本会连带附件一起删。**自己做的测试记得删干净。**

## 常见报错

| 报错 | 原因 |
|---|---|
| `Missing required scopes: repo-release:rw` | 用的是 OAuth token，换 PAT |
| `缺 CNB_TOKEN` | 没 `. ~/.cnb/agent-token` |
| `verify_url 解析不出 token/path` | CLI 版本变了，对照 §手工跑 重新抠字段 |
| `服务端算的 sha256 和本地对不上` | 传输被截断，重跑；upload_url 12 小时内可复用 |
| `回读不到服务端 sha256` | 确认步骤没成功，附件可能处于半上传状态，重跑 |
