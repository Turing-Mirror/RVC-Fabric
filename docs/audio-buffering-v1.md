# 实时音频缓冲修复 v1

2026-10-18 的两份 1.7.0 工单报告：采样块超过 0.06 秒后断音，长块下无声，原声监听同样受影响。

原生音频桥一次收到完整的推理块，却立即将它灌入播放和监听队列。监听把正常音频块当成超过 60 毫秒的积压而丢弃；桥接读取另有固定 400 毫秒截断，超过 1 秒的块则超出共享缓冲容量。

修复后，共享缓冲容量和积压上限随本次启动的采样块时长调整，并为 10 毫秒的工作块取整预留空间。读取按播放队列的消耗推进，最多提前约 30 毫秒，完整音频块留在共享缓冲中等待播放。监听仍保留独立设备时钟漂移的积压控制。

回归覆盖 44.1/48 kHz 下 0.06、0.28、0.58、1.13、1.5 秒的完整块读取、播放和监听，及 Python 端长块发布。界面和模型算法不变。
