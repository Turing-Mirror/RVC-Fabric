# 音频库阶段六实现状态

更新于 2026-09-23，分支 `tm-release`。本阶段接续[阶段五](音频库阶段五实现状态.md)。

## 已实现

- Windows 上，用户指定语音输出设备后，原生端在变声启动前打开一条持久输出流。RVC 或 DSP 只采集麦克风，将处理后的 PCM 写入有界共享映射；原生端把它与音频库播放合入同一输出流。音频切换只替换混音槽，不重开设备。
- 变声停止时仅撤下麦克风轨，已播放的音频可以继续；停止音频也不结束正在运行的麦克风轨。重复启动、更换运行中的输出设备、同设备本地试听均有明确拒绝路径。
- 桥接写入与停流关闭已串行化，重启时会清理旧桥接参数。原生输出或桥接读取失败时，底栏保留变声运行态并提示用户停止、重新开启。
- 未指定语音输出设备时仍走原有 RVC／DSP 输出路径；macOS 暂不启用原生麦克风桥接，音频与变声保持互斥。

## 本机检查

- 音频核心混音定向测试、Rust 原生端定向测试、Python 桥接与旧音频环测试通过。
- 前端类型检查、音频页测试和 8 语言包一致性检查通过；Windows 目标静态编译通过。

## 待 Windows 实机验收

- RVC、DSP 与虚拟声卡的实际混音、延迟、音量和重采样听感；设备拔插、异常退出、快速启停与模型热切换。
- 当前本地监听仍沿用 Python 既有监听流，尚未统一到原生总线；原生服务目前只接单个变声麦克风实例。多实例路由、快捷键和状态悬浮窗不属于本阶段。
