# 训练队列 v1

训练窗口使用持久队列，底层仍执行 `tools/train_worker.py` 的预处理、音高、特征、训练和索引五个阶段。原有直接训练 API 与 `train-progress` 事件保持兼容。

## 操作

- 表单始终可以编辑并添加任务。任务按加入顺序执行，同时只运行一个训练任务。
- 每条任务展示状态、当前阶段、轮数及预计剩余时间。详细原始输出仍保留在训练日志。
- 等待任务可以移除；正在运行的队列任务可以停止；失败、取消或中断任务可以使用原参数重试；已结束记录可以清除。
- 切换页面、关闭工具窗口再打开时，界面重新读取原生队列。完成试听只关联当前实验名的最新任务。

## 参数与文件

队列保存在 `User_Data/train_queue.json`，通过临时文件完整写入后替换。加入时固定实验名、素材目录、采样率、轮数、批次、保存选项、音高算法、续训选项、输出目录和 CPU/CUDA 设备选择。之后修改表单或全局设备设置不会更改已有任务。

素材保留目录引用，不复制音频。运行前仍由原有预检检查文件；排队期间修改或删除素材会影响之后执行的任务。实验中间文件仍位于 `logs/<实验名>`，成品仍由原管线写入默认 `User_Data/models` 或所选目录。移除队列记录不会删除素材、模型或实验文件。

重新启动应用后，未开始任务变为暂停，运行中任务变为中断。用户明确选择继续或重试后才会执行，不自动启动 GPU 工作。重试保留原请求，是否复用已有阶段由原请求的续训选项和原训练管线决定。

## 并发边界

队列等待实时变声停止，也等待原有直接/API 训练结束，不自动打断它们。实时启动和训练共享短时入口锁，防止同时启动；训练期间实时启动返回明确的忙碌提示。队列的停止操作携带任务所有者，只能终止该任务的训练进程，不会误停随后开始的任务或直接 API 训练。原有直接训练请求及其取消接口保留原语义。
