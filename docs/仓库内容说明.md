# Git 仓库里有什么 / 没有什么

> 面向：克隆本仓库的开发者、在 GitHub 上阅读代码的人、后续 AI 对话。  
> 仓库地址（组织）：https://github.com/Turing-Mirror/TuringMirror-Voice  
> 默认开发分支：`tm-release`

---

## 一句话

**本仓库 = 源码 + 文档 + 打包脚本。**  
**不是**「解压就能变声」的完整安装包；绿色 Python 环境、大模型权重、ffmpeg、打好的 exe 等体积大或属本机产物，默认不进 Git。

GitHub 单文件硬限约 **100MB**；当前已跟踪文件均远小于此，**无需 Git LFS**。

---

## 包含（会进入 GitHub）

| 类别 | 路径 / 说明 |
|------|-------------|
| 产品壳 | `launcher/`（主界面、启动器、实时 client、GPU/包元数据、VBS 等） |
| 引擎入口 | `gui_v1.py`、`infer-web.py` |
| 推理/训练代码 | `infer/`、`configs/`、`i18n/`、`tools/`（含 `realtime_worker.py`） |
| 开发启动 | 根目录 `start.bat` / `start_app.bat` 等薄入口，`scripts/dev/` |
| 打包脚本 | `scripts/build_release.py`、`.bat` 等 |
| 依赖清单 | `requirements/`、`pyproject.toml`、`poetry.lock`、`requirements.txt` |
| 文档 | `docs/` 全部说明与交接文档、`README.md`、`LICENSE` |
| 测试与其它 | `tests/`、`docker/`、`notebooks/`、`.github/` |
| 轻量占位 | `User_Data/README.md`、`.gitkeep`；`logs/mute/` 等极小 mute 样例 |
| 资源目录结构 | `assets/` 下的目录与占位说明（**不含**大体积预训练权重本体） |

典型体量：约 **300 个以内** 源文件，以 `.py` / `.md` / `.json` 为主。

---

## 不包含（本机可有，默认不进 Git）

| 类别 | 典型路径 / 说明 |
|------|-----------------|
| 绿色 Python 环境 | `Runtime/`（含 torch 等，数 GB 级） |
| 发行成品目录 | `dist/`、`build/`、根目录 `变声器.exe` / `启动器.exe` / `TM_*.exe` |
| 预训练大文件 | `assets/hubert/*.pt`、`assets/rmvpe/rmvpe.pt`、`rmvpe.onnx` 等 |
| 编解码二进制 | 根目录 `ffmpeg.exe`、`ffprobe.exe` |
| 用户/预置音色 | `User_Data/models/**/*.pth`（以及本机配置、日志） |
| 本机状态 | `User_Data/app_config.json`、`User_Data/runtime_control/`、`User_Data/logs/*` |
| 构建与调试缓存 | `TEMP_BUILD/`、`TEMP/`、各类临时 log |
| 虚拟声卡安装包本体 | `VBCABLE/` 下 `.exe` / 驱动等二进制（目录可有说明性小文件） |
| 本机环境变量文件 | `.env` |

这些由打包机或开发机通过：

- 官方/自备绿色环境与权重，或  
- `scripts/build_release.py` 组进 **`dist/` 发行文件夹**  

再分发给最终用户。最终用户应使用 **发行包**，而不是只 clone 本仓库。

---

## 克隆后如何跑起来（开发视角）

1. 准备 **Runtime**（内含可用的 Python 与 torch/CUDA 或 DirectML，视目标显卡而定）。  
2. 准备 **hubert / rmvpe** 等权重与 **ffmpeg**（放到文档约定的路径）。  
3. 可选：预置 `User_Data/models` 音色。  
4. 开发：`start.bat` / `start_app.bat`（见 `scripts/dev/`）。  
5. 打用户包：`scripts/build_release.py`（`--variant nvidia|amd|nvidia50` 等，见 `docs/发行包-显卡分版.md`）。  

详细步骤见：

- `docs/发行版打包与用户使用.md`  
- `docs/发行包-显卡分版.md`  
- `docs/CONTEXT_HANDOFF.md`

## 和「发行包」的区别

| | Git 仓库 | 发行包（`dist/...`） |
|--|----------|----------------------|
| 给谁 | 开发者 / 审代码 | 最终用户 |
| 是否含 Runtime | 否 | 是（按显卡变体） |
| 是否含大模型权重 | 否（需自备或打包时拷入） | 打包时打入 |
| 是否含 exe | 否 | 是（启动器 / 变声器） |
| 用户操作 | clone、改代码、再打包 | 解压 → 双击 exe |

---

## 维护约定

- 新增 **大二进制**（模型、CUDA 轮子、完整 Runtime）前，先确认是否应走 **发行打包** 而非 git。  
- 若某文件将 **超过约 50–100MB** 且必须进库，需单独评估 Git LFS 或外链，**不要默认 commit**。  
- 更新本说明时保持与 `.gitignore` 一致。
