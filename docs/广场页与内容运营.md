# 广场页与内容运营 — plaza.json 规范与投放手册

> 实现代码：`launcher/online/plaza.py`（feed 解析 / 过滤 / 排序 / 缓存的**唯一权威**，schema 以它为准）  
> 更新日志：`launcher/online/changelog.py` + `catalog-src/changelog.yaml`  
> 界面：主界面导航 **「广场」**（快捷键 `Ctrl+5`）+ 模型页顶部可关闭横幅  
> feed 直链：`https://cnb.cool/Turing-Mirror/RVC-Fabric-Releases/-/git/raw/main/plaza.json`  
> 更新日志：`…/changelog.json`（独立文件）

---

## 1. 概览

广场页是产品内的**资讯位**：TRM / RVC Fabric 官方动态（维护公告）、
社群引流（B 站 / 官网 / QQ 群）、赞助 / 广告，以及固定的 **「更新日志」** 区块。

**feed 与发版解耦**——`plaza.json` / `changelog.json` 均独立于 `index.json`，运营改内容
**不需要发版**；改完 push CNB 仓即生效（客户端下次拉取可见）。

客户端行为摘要：

| 行为 | 说明 |
|------|------|
| 后台预取 | 启动约 3 秒后后台拉取 plaza + changelog，失败静默回落缓存，**绝不影响主流程** |
| 未读角标 | 导航「广场·新」仅针对 plaza 资讯 id（**不含**更新日志未读） |
| 更新日志区块 | 主列表固定分区，**只展示最新一条**；点「查看全部」进入广场内二级页（可返回） |
| 模型页横幅 | `placements` 含 `models_page` 的条目**至多展示一条**，且**必须可关闭** |
| 离线 | 缓存 `User_Data/update_cache/plaza.json` 与 `changelog.json` |
| 点击 | plaza 卡片 `on_card_clicked` 开浏览器；更新日志二级页仅本地展示 |

## 2. 管线：plaza.yaml / changelog.yaml → JSON

| 环节 | 位置 / 命令 |
|------|-------------|
| 广场资讯源 | `CNB-GIT-RELEASE\catalog-src\plaza.yaml` |
| **更新日志源（壳说明单一源）** | `CNB-GIT-RELEASE\catalog-src\changelog.yaml` |
| 编译 | `python scripts\build_catalog.py build --diff` |
| 校验 | `python scripts\build_catalog.py check`（回环过真实客户端解析器） |
| 生成物 | `plaza.json`、`changelog.json`、与 index / snippet / bundled（**勿手改**） |

流程：

```text
改 catalog-src\plaza.yaml 和/或 changelog.yaml
  → build_catalog.py build --diff
  → push CNB-GIT-RELEASE
```

### 2.1 更新日志（changelog）规范

| 项 | 规则 |
|----|------|
| 维护 | **只改** `changelog.yaml`；`app.gui.notes` 由最新条**自动覆盖** |
| 范围 | 仅正式 Base + hotfix 全文；**从现在起正向积累**（不强制回填更早版本） |
| version | 与壳 Full 一致：`X.Y.Z` 或 `X.Y.Z-hotfixN` |
| highlights | 可选；广场主卡摘要优先 |
| body | 建议必填；全文 + 设置页更新说明来源 |
| 广场 UI | 主列表固定「更新日志」区只露**最新一条**；「查看全部」→ 二级页（**返回**回主列表） |
| 与 release news | 默认仍生成 `id=release-<version>` 资讯供**旧客户端**；**新客户端**有 changelog 数据时主列表**隐藏** `release-*`，避免双份 |
| 不可关闭 | 日志不是广告，无 dismiss |
| 未读角标 | **不**计入「广场·新」 |

发版 checklist：先写 `changelog.yaml` 新条 → 升 `APP_VERSION` / `app.yaml` version → `pack_gui_patch` → `build_catalog`。

## 3. 字段参考（plaza.yaml 每条 item）

| 字段 | 说明 | 默认 |
|------|------|------|
| `id` | **必填**；全局唯一稳定字符串，已读 / 关闭都按 id 记账，发出去就别改 | — |
| `type` | `news` / `notice` / `banner` / `ad` / `sponsor`；不在此列的整条被旧客户端忽略 | `news` |
| `title` | **必填**；卡片标题，缺失整条丢弃 | — |
| `body` | 正文（别名 `text` / `desc`） | 空 |
| `image` | 图片：CNB 仓内相对路径（推荐 `plaza/xxx.jpg`）或 cnb.cool https 直链；**外部图床直接丢弃** | 无图 |
| `url` | 点击跳转链接；仅 http/https，其余丢弃 | 无跳转 |
| `action_label` | 按钮文案（如「去围观」「加群」） | 空 |
| `date` | 展示日期 YYMMDD（YYYYMMDD 会自动归一） | 空 |
| `priority` | 整数，越大越靠前（别名 `weight`） | `0` |
| `pinned` | `true` 置顶（优先级最高的排序键） | `false` |
| `dismissible` | 用户可关闭；**ad / sponsor 强制为 true，feed 写 false 也无效** | `false` |
| `placements` | `plaza` / `models_page`，可多选；决定卡片出现在广场页还是模型页横幅 | `[plaza]` |
| `start` | 投放窗口起始 YYMMDD（含当天）；空 = 不限 | 空 |
| `end` | 投放窗口结束 YYMMDD（含当天）；空 = 不限 | 空 |
| `min_app_version` | 最低客户端版本（`compare_versions`，含 `-partN` 语义），低于则隐藏 | 不限 |
| `max_app_version` | 最高客户端版本，高于则隐藏（旧功能引流用） | 不限 |
| `sponsor` | 广告主名；**非空即视为广告**（强制可关 +「广告」角标） | 空 |
| `utm` | 编译期开关：是否给 `url` 自动追加 utm 参数（见 §5）；此字段不进 plaza.json | ad/sponsor 为 `true` |

排序规则（客户端固定，运营只能靠字段影响）：`pinned` 置顶 → `priority` 降序 →
`date` 新在前 → `id` 升序兜底（确定性）。

## 4. 关键语义（运营必读）

- **按 id 永久关闭**：用户点 × 后该 id 永不再现（存本地配置）。**想让同一内容重新曝光，
  必须换一个新 id**——复用旧 id 等于对关过它的用户永久隐身。
- **ad / sponsor 强制可关闭，客户端强制显示「广告」角标**（`sponsor` 字段非空同样触发）。
  这是广告法可识别性要求 + 产品承诺，feed 无权关掉这个开关；不可关闭的条目也**没资格**
  上模型页横幅。
- **未知 `type` 被旧客户端静默忽略**：将来加新卡片类型只需新 feed + 新客户端，
  旧版不炸不乱——所以加新类型不必等全量升级。
- **图片必须先入 CNB 仓**（`plaza/` 目录），feed 里写相对路径；**不允许外部图床 / 跟踪像素**，
  非 cnb.cool 域名的图片 URL 客户端直接丢弃（供应链可控）。
- **版本资讯条目由 `app.yaml` 自动派生**：发新版时 build_catalog 自动生成一条发版 news，
  不用在 plaza.yaml 里手写；不想要就在 app.yaml 里设 `auto_release_news: false`。

## 5. 数据与统计立场

**客户端零遥测**——不上报任何数据：没有曝光打点、没有点击回传、没有设备信息。

点击统计走**编译期 utm 盖章**：`build_catalog.py` 自动给 `ad` / `sponsor` 条目的 `url`
追加：

```text
utm_source=rvc_fabric&utm_medium=<位置>&utm_campaign=<id>
```

`<位置>` 即 placement（`plaza` / `models_page`），`<id>` 即条目 id。落地方
（B 站 / 官网 / QQ 群落地页）在自己的来路统计里看 utm 即可核对投放效果。
曝光的近似值可看 CNB 上图片文件的访问量（如平台提供该数据）。

### 未来若上 beacon 的铁律

某天真要做曝光统计，只允许改 `plaza.py` 的 `on_card_clicked` / `mark_seen` 两处，且：

- 上报端点**硬编码在代码里**，feed **永远无权**指定任何上报 URL 或参数
  （防 feed 被劫持后驱动全体装机量发请求）；
- payload 仅 `campaign_id` + `event` 两个字段，不带任何设备 / 用户信息；
- 每会话每条**至多一次**；
- fire-and-forget，失败**不重试**；
- 设置页提供开关，可整体关闭。

---

## 6. 权限边界

**CNB 制品仓（RVC-Fabric-Releases）的写权限 = 广告投放权限**——能 push `plaza.json`
就能向全体用户投放内容。因此 `plaza.yaml` 的修改必须过维护者审核，不下放；
协作者提投放需求走 PR / 找维护者代发。

## 7. 客户端排障

| 项 | 位置 |
|----|------|
| feed 缓存 | `User_Data/update_cache/plaza.json` |
| 图片缓存 | `User_Data/update_cache/plaza_covers/`（URL 哈希命名） |
| 已读 id | `User_Data/app_config.json` → `plaza_seen_ids`（上限 200 条滚动） |
| 已关闭 id | `User_Data/app_config.json` → `plaza_dismissed`（上限 200 条滚动） |
| 打开广场页 | 快捷键 `Ctrl+5`；导航顺序 首页 · 模型 · 广场 · 设置 · 说明 · 其他 |

| 现象 | 原因 | 处理 |
|------|------|------|
| 广场页空白 | 离线且无缓存，或 feed 全部条目不满足版本 / 投放窗口 | 联网重开；核对 `min_app_version` / `start` / `end` |
| 图片不显示 | 图片不在 CNB 仓（外部图床被丢弃）或路径写错 | 图片入仓 `plaza/`，feed 写相对路径 |
| 关闭的广告想再展示 | 按 id 永久关闭，无法恢复 | 运营侧换新 id 重新投放 |
| 条目排序不对 | 排序规则固定 | 调 `pinned` / `priority` / `date` |
| 模型页横幅不出现 | 条目不可关闭，或 `placements` 缺 `models_page` | 设 `dismissible: true` 并加 placement |
